# 给 Claude Code 的提示词：只看内容，自己决定如何嵌入 Prophub

你现在正在开发 GitHub 仓库 `prophub`。这个项目已经在做了，网站结构、页面和设计都以你当前仓库为准。

我现在给你一包 Prop Firm 内容资料，不是让你重做网站，也不是让你照搬别人的页面。

你的任务很简单：

**先认真阅读这些文字内容，然后结合 `prophub` 现有项目，判断这些内容应该怎么自然嵌入当前网站，让用户愿意停留更久、继续点击、反复回来查资料。**

内容包里最重要的是：

```text
content-knowledge-base/
content-knowledge-base/knowledge-base.json
content-knowledge-base/01_site-logic.md
content-knowledge-base/02_platforms.md
content-knowledge-base/03_guides.md
content-knowledge-base/04_software-payout-flows.md
content-knowledge-base/05_raw-page-text.md
```

请不要一上来就改代码。先做这几步：

1. 阅读 `prophub` 当前代码结构，理解现有网站已经有什么。
2. 阅读 `content-knowledge-base` 的内容，理解里面有哪些平台资料、攻略、规则、软件教程、出金教程、风险披露。
3. 判断这些内容最适合嵌入到当前网站的哪些位置。
4. 再用最小改动把内容接进去。

不要做：

- 不要重做网站
- 不要重做首页
- 不要推翻现有设计
- 不要新建一套完全独立的站
- 不要为了内容包改变现有产品方向

你应该做：

- 复用现有页面和组件
- 把平台资料放到适合的平台/对比/详情区域
- 把攻略内容放到适合的学习/文章/知识库区域
- 把软件教程和出金教程放到用户决策路径里
- 给文章和平台之间加自然内链
- 让用户读完一页后知道下一页该看什么
- 让内容服务 Prophub 当前产品，而不是让 Prophub 迁就内容包

重点思考：

- 哪些内容适合直接展示？
- 哪些内容适合作为详情页补充？
- 哪些内容适合作为 FAQ？
- 哪些内容适合作为“继续阅读”？
- 哪些内容适合做平台对比字段？
- 哪些内容只是后台数据，暂时不展示？

内容目标：

- 提高页面停留时间
- 增加连续点击深度
- 帮新手从零理解 prop firm
- 帮用户比较平台
- 帮用户查规则
- 帮用户理解付款、KYC、出金、软件连接
- 让 Prophub 看起来像一个长期可查的知识库，而不只是一个展示页

合规要求：

- 不要承诺收益
- 不要写包过
- 不要写稳赚
- 不要写稳定出金
- 不要写保本
- 不要提供喊单、带单、代操、代付、代 KYC
- 平台规则、费用、地区限制要提示“以上游官网最新说明为准”
- 涉及返佣链接时必须有返佣披露

完成后请告诉我：

1. 你读完内容后，认为最适合嵌入 Prophub 的内容模块有哪些。
2. 你实际改了哪些文件。
3. 哪些内容已经在网站里可见。
4. 哪些内容还只是保留在资料库里。
5. 你如何设计用户继续阅读/继续点击的路径。
6. 哪些平台规则和链接仍需要人工核验。

一句话总结：

**不要照着内容包建站，而是把内容包当作资料库，融入正在开发的 Prophub。**
